# こかげマップ コンセプト

> [!NOTE] 2026-08-21 全面改訂
> 旧版は「お絵描きアプリのような操作性のモバイルGISアプリ」を identity として定義していたが、
> 製品の重心が動いたため書き直した。詳しい経緯は Vault の 競合調査_2026-08-21 を参照。
> 旧版の内容は git 履歴に残っている。

## 一行で

**山の現場で、追加の道具を何ひとつ用意せずに使える GIS。**

## 何で戦うか: 機能の多さではなく「前提条件の少なさ」

同種のツールは、たいてい何かを要求する。

| ツール | 要求されるもの |
|---|---|
| QField | QGISプラグイン（QFieldSync）でのパッケージ化 / 同期には QFieldCloud（無料100MB、以降 €18/user/月）/ フリーハンド描画はスタイラスかマウス |
| Mergin Maps | 自社クラウド（またはセルフホスト）/ スケッチはQGIS側で事前設定が必要 |
| 圏外向け位置共有（GeoChat・Soko-co 等） | 無線機・基地局・中継機などの専用ハードウェア |
| ArcGIS Field Maps | Esri のライセンス |

こかげマップ は**そのどれも要求しない**。

- スタイラス不要（指で描ける）
- 専用クラウド不要（同期はユーザー自身の Google Drive）
- QGIS プラグイン不要（GeoPackage をそのまま開く）
- アカウント不要（ローカルで完結する）
- 専用ハードウェア不要（位置共有はスマホだけで成立する）
- ユーザーがサーバーを立てない（非エンジニアでも「ホスト」できる）

**これが identity。** 個々の機能はこの原則から導かれる。

## 中核機能（重要度順）

### 1. パーティ（圏外前提の位置共有）

目印のない山中で別行動すると、互いの居場所が分からなくなる。
ルームコードで参加し、全員の位置を地図上でリアルタイム共有する。

**設計の核は「山中は常に圏外と考える」**こと。トンネルもサーバー障害も区別せず統合的に扱う。

- 途絶中はリトライせず電池を温存する
- 復帰の瞬間を的確に検出して再開する（`.info/connected`）
- **圏外だった区間の軌跡を、復帰後にGPS履歴から埋める**
- トランスポート非依存（cell / wifi / 衛星のどれで復帰しても同じ経路）

設計の詳細は [[../technical/location-sharing|位置共有設計]]。

> [!IMPORTANT] 住み分け
> 無線機・衛星端末を使う方式は**圏外中もリアルタイムで届く**。
> 緊急時（怪我・遭難）はそちらが本命であり、そこと competing しない。
> こかげマップ は「復帰後に埋める」であって「圏外中も届く」ではない。

### 2. 自分の Google Drive で同期する

プロジェクトフォルダを Drive と同期する。**ユーザーが既に持っているストレージを使う**ので、
容量課金も追加サーバーも発生しない。

### 3. 現場計測（TruPulse 連携）

TruPulse 360R を Bluetooth で直接叩き、閉合補正（コンパス法則 / トランシット法則）・
磁気偏角補正・器械高補正まで行う。測った結果はそのまま地図上のフィーチャになる。

### 4. GeoPackage をそのまま扱う

変換もパッケージ化もせず、ユーザーの `.gpkg` を直接読み書きする。
**QGIS との往復で壊れないこと**を重視する（[[../technical/qgis-interop|QGIS相互運用]]）。

### 5. 直感的な描画・編集

指でなぞって線やポリゴンを描ける。**これは差別化そのものではなく、
「前提条件の少なさ」の一例**として位置づける（スタイラスを要求しない、という意味）。

## ターゲットユーザー

- **林業の現場**（森林組合・素材生産業者・自伐林家）— 主戦場
- フィールド調査を行う研究者・技術者
- GISの専門知識はないが、位置情報付きの記録を作りたい人

## プラットフォームの役割分担

| | 役割 | 理由 |
|---|---|---|
| **Android** | **製品の本体** | TruPulse測量・GPS軌跡の常時記録・オフライン。現場機能はここにしか置けない |
| **Web** | 閲覧・共有・事務所作業 | インストール不要。**ルームへの参加がURLで済む**ことは主力機能の強化にあたる |
| ~~Windows / macOS / Linux~~ | **2026-08-25 に撤去** | web版がGeoPackageの読み書きまで到達し、役割を引き継いだ |

> [!WARNING] デスクトップ版を消したことの代償
> **オフラインで配れる実行ファイルが無くなった。** 配布はURLかPWAインストールだけ
> （[[#配布と運用コスト（2026-08-25 決定）|配布と運用コスト]]）。「ネットの無い場所にUSBでアプリを渡す」が要るなら、
> `flutter create --platforms=windows .` でビルド対象を戻すところからやり直す。

## 配布と運用コスト（2026-08-25 決定）

> [!IMPORTANT] web版は普通に公開する。自己ホストは既定にしない
> 「使いたい人は自分でサーバーを立てて」は、QFieldCloud や Mergin Maps の自社クラウドと
> **同じ土俵に降りる**ことになり、identity の「ユーザーがサーバーを立てない」を捨てる。
> セルフホストは**大口が自前で回したいときの選択肢**として残すだけ。

### 配り方

Flutter の web ビルドは**HTTPサーバー越しでないと動かない**（`file://` では
fetch がCORSで止まり、`SharedWorker`（sqlite3 WASM）も作れない）。
ダブルクリックで起動する実行ファイルにはならない。配り方は次の2つ。

- **URLを渡す** — インストール操作ゼロ。web版の存在理由そのもの
- **PWAとしてインストールしてもらう** — 一度入れればデスクトップのアイコンから起動できる

### コストがどこに出るか

サーバはアプリの静的ファイルを配るだけで、**データは一切通らない**
（GeoPackageはユーザーのローカル、タイルはOSM/国土地理院から閲覧者が直接取得）。

| | 実測・上限 | 効き方 |
|---|---|---|
| アプリ配信 | gzip後 2.5MB/初回（canvaskit 31MB は gstatic 持ち） | Hosting無料枠 360MB/日 ≒ 新規140人/日。以降キャッシュ |
| ルーム通信 | 約2.3MB/ルーム日（移動中75秒・静止中3分ごと publish） | RTDB無料枠 10GB/月 ≒ 約4,000ルーム日 |
| **同時接続** | **Spark は100・引き上げ不可** | **ここだけが実質の天井**。5人パーティなら同時20組 |

⚠ 有料化の引き金は転送量ではなく**同時接続数**。Blaze に上げても無料枠は維持されるので、
上げても実費はほぼ立たず、**接続数の天井が外れるだけ**。
ただし Blaze は上限の無い従量課金なので、上げるなら予算アラートを必ず設定する。

### 将来ここは実費が出る

`公開ビューア（PMTiles/GeoJSONを静的ホスティング）` は、**自分のデータを自分のホストから配る**
初めての機能になる。着手時に転送量を見積もり直すこと。
