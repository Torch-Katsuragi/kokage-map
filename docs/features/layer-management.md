# レイヤー管理機能

Adobe Frescoのような直感的なレイヤーパネルを提供します。

## フォルダ構造とGeoPackageファイルに連動したレイヤー/レイヤーグループ

- プロジェクトフォルダ内のサブフォルダ構造が、Root Maps内のレイヤーグループ階層としてそのまま反映される。
- 各フォルダ内に存在するGeoPackageファイル（.gpkg）は、そのフォルダに対応するレイヤーグループ内に「GeoPackageソース」のような特別なアイテムとして表示される。
- 「GeoPackageソース」アイテムを展開すると、そのGeoPackageファイル内に保存されている各レイヤーが一覧表示される。
- これにより、「フォルダグループ → （サブフォルダグループ / GeoPackageソース → GeoPackage内部レイヤー）」という階層構造を実現する。

## この端末（sys）

`sys` は**プロジェクトに属さない、端末側の層**。どのプロジェクトを開いても、ツリーのルート直下に 1 つだけ出る仮想フォルダ（2026-09-25〜）。

```
Home（プロジェクト）
├─ この端末（sys）   ← 仮想。実体ディレクトリは無い
│  ├─ Global        ← グローバルフォルダ（編集できる）
│  └─ （view）      ← 未実装・要判断
├─ フォルダA
└─ ...
```

- 表示名は i18n（日本語「この端末」、英語「This device」）。内部の名前（可視性の鍵）は `<sys>`
  - ファイル名に使えない文字にしてあるのは、プロジェクト直下に `sys` という実フォルダがあっても取り違えないため
- プロジェクトの Drive 同期・`.qgs` 書き出しの**対象外**。sys 自体はリネーム・削除・ドラッグ・Drive 連携をしない
- アイコンは端末、色はグローバルと同じ青（`NodePresenter`）
- web ではグローバルフォルダを作らないので、sys も出ない
- 実装は `SysNode`（[[lib/models/nodes/sys_node.dart]]）。`FolderNode` を継承し、パスは持たない（`getAbsoluteFilePath()` が null）

### sys/global（グローバルフォルダ）

- 実体の場所は `GlobalFolderLocator` が決める（Android の既定は共有ストレージの `Documents/KokageMap/Global`）。**実体は動かさず、ツリー上の位置だけ sys の下に置いた**
- 中身は通常のフォルダと同じく編集できる（GeoPackage・写真・サブフォルダの追加、地図上での表示・編集）
- 配下のサブフォルダは今までどおり**個別に** Drive 連携できる。プロジェクトの Drive 連携とは別物
- global 本体はリネーム・削除・ドラッグの対象にしない（実体の場所はアプリが決めているため）
- 可視性の保存先はプロジェクトルートの `.kmeta.json` の `folders['Global']`。ルート直下にあった頃と同じ鍵なので、保存済みの表示状態はそのまま残る。sys 自身は `folders['<sys>']`
- global 配下のパスは「リゾルバの起点（global）より下」の名前から組み立てる。ツリー上の深さを決め打ちしない（`LayerTreeNode.getAbsolutePathSegments`）
- global や、その下の Drive 連携dirに `.kmeta.json` があれば、そこには従来どおり自分の `.qgs` を書く。プロジェクトの `.qgs` には載せない

### sys/view（未実装・要判断）

端末の写真など、**読み取り専用の仮想レイヤ**を置く想定。今回は作っていない。先に決めることが 2 つある。

- 権限: 端末の写真を一覧で読み、位置情報まで取るには写真の読み取り権限と `ACCESS_MEDIA_LOCATION` が要る。Google Play の写真・動画の権限ポリシーでは、写真への広いアクセスを中核機能として申告する必要がある。いまの用途（ギャラリーからの取り込み）とは別の説明になる
- 性能: 端末の写真は数千〜数万枚ある。ツリーに 1 枚ずつノードとして並べる今の作りでは重い。EXIF の読み込みを間引く・索引を持つ・地図の範囲で絞る、などの設計が要る

## レイヤー操作

- レイヤー/レイヤーグループ/GeoPackageソースの追加、削除、複製、名称変更。
  - フォルダやGeoPackageファイルの操作は、実際のファイルシステム構造にも反映される（またはその逆）。
- レイヤーの表示/非表示切り替え（個々のレイヤー、GeoPackageソース全体、フォルダグループ全体）。
- レイヤー/レイヤーグループ/GeoPackageソースの順序変更（ドラッグ＆ドロップ）。
- レイヤーごとの透過度設定。
