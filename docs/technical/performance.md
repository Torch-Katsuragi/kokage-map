# 性能（電池・メモリ・起動）

2026-10-06 にまとめて洗い直した記録。数字は Pixel 11 Pro Fold（折りたたみ・1080×2342）、プロジェクトはいつもの地図に
龍神村の森林簿（小班 1.5 万面・61.7 万点、EPSG:2448）を入れたもの。debug は JIT なので CPU・メモリは profile の数字を正とする。

## 結果

| 項目 | 前 | 後 | 測り方 |
|---|---|---|---|
| 地図を開いて置いたままの CPU | 45〜117%（debug） | 7〜14%（debug・profile とも） | `top -p <pid>` を 5 秒おき |
| パン後の GL（GPU のメモリ） | 0.8〜1.2GB（debug） | 520〜590MB（profile） | `dumpsys meminfo` の GL mtrack |
| 全体の PSS（パン後） | 2.38GB（debug） | 1.21GB（profile） | 同上 |
| 木の読み込み〜地物が揃う | 10.2 秒 | 6.1 秒 | `[Init] projectTree start` 〜 `[Features]` |
| 最初のタイルが届くまで | 約 5.7 秒 | 約 1.2 秒 | 同上の `[TILE] cache hit` |
| パン中の遅延フレーム（profile） | — | 0.5%（90% 点 5ms） | `dumpsys gfxinfo` |

## 直したこと（効いた順）

### 置いたままで動き続けていたもの

- **コンパス**: 平滑化した向きが同じ値に落ち着かず、センサーの速さ（15〜60Hz）で地図全体を描き直していた。
  0.5° 未満は知らせず、3D は現在位置の扇の 5° 刻みをまたいだときだけ描き直す。裏に回ったら購読を解く
  （⚠ ブロードキャストの購読を pause すると止めている間の値を溜め込むので、cancel して付け直す）
- **GPS**: フォアグラウンドサービスが同じ位置を毎秒送り直し、そのたびに地図ページ全体を組み立て直していた。
  同じ位置・表示に関わる値が同じなら組み立て直さない。通知の書き換えは位置が変わったときか 15 秒おき
- **GPS 軌跡の統合（20 秒ごと）**: 全地物の一覧を作り直し → 1.5 万面の GeoJSON 変換 → 全タイルのシーン作り直し → 下地の焼き直し、
  と連鎖していた。[[#地物の一覧を保つ]]。軌跡のレイヤも丸ごと読み直していたのを、今日の区間の 1 本の差し替えに。
  その後も全地物の集め直しと焼き直し（6 枚）が残っていた → [[#2026-10-12 置いたままの焼き直し（d2/rebake-loop）]]

### メモリ

- **GPU の描画先**: `GpuImageSurface` は Flutter から参照されている描画先を使い回さずに足す作りで、フレームごとの参照
  （`currentImage`・フレームの `colorTexture` のラッパー）が GC まで残り、描画先（画面サイズ・約 10MB）が 46 → 65 枚と増えていた。
  自前の色テクスチャ 3 枚を順に使い `asImage()` で渡す（`lib/core/terrain/gpu/terrain_gpu_world.dart`）。
  `debugBackingTextureCount` で数えて突き止めた。画像キャッシュを縮めても減らなかった（主因ではない）
- 見えなくなったオーバーレイ画像を手放す

### 地物の一覧を保つ

`FeatureGeoJsonCache`（`lib/screens/map_page/feature_geojson_cache.dart`）は、地物ごとに「turf の形と属性が同じなら前の変換結果」を
使い回し、全件が同じなら**リストそのものを前のまま返す**。描画側はリストの同一性でキャッシュを引く（タイルのシーン・地物の範囲の索引）
ので、これで統合のたびの作り直しが止まる。

- レイヤを読み直さない限り turf の形は同じオブジェクト。編集は新しい形を `addFeatureToMap` するので、同一性で見てよい
- タイルの静的シーンは、変わった範囲（焼き直しの台帳 `FeatureBakeLedger` の記録）がタイルに掛からなければ鍵だけ差し替えて使い続ける
- 選択・頂点・写真の一覧も同じく保つ（どれかが毎回新しいと、シーンの使い回しが一度も効かない）

### 起動

- **地物の読み込み**: 1.5 万面（24MB）を 1 回の問い合わせで読むと、1 通のメッセージがプラットフォームチャネルを塞ぎ、
  タイルキャッシュの読み出しまで 2.5 秒待たされていた。2000 行ずつ読み、ページごとに isolate で解析を始める
- 別の isolate で SQLite を直接開く案は採らない（同じファイルを別々の SQLite が開くと、片方が閉じたときにロックが外れて壊れうる。
  `GeoPackageConnection` の注意書き）

### 操作中

- 選択: タップのたびに全件組み直しの合図を引いていたのをやめる（選択の一覧だけ組み直す経路がある）
- 当たり判定: 地物の範囲で先にふるう（全頂点を毎回なめていた）
- ペン: 描きかけの線の範囲に掛からないタイルでは線を組まない。点の一覧を呼ぶたびに複製していたのを変わったときだけに
- 属性表: 表の通知のたびに選び直していたのを、今いる行が変わったときだけに

### そのほか

- 画像処理（細かい段の背景地図の切り抜き・GeoTIFF → PNG）を常駐の `TerrainWorker` に
- タイルキャッシュ: DB を開いている間はファイルの有無の同期確認を省く
- リリースでは `debugPrint` を黙らせる（`K_LOG` のときは残す）
- web: GeoPackage の書き戻しは書き込みが落ち着いてから（続いていても 10 秒で書く）、タブを隠したときはすぐ書く

## 2026-10-07 の大掃除で入った軽量化

数字は測っていない（計画系だけデスクトップのテストで 25〜35% 減）。どれも結果は変えない前提で、テストで固定した。

- 地図ページ: パーティの状態・編集の状態を watch しない／絞る（仲間の位置や頂点のドラッグでページ全体を組み直していた）。
  描いた地物の確定で焼き込み済みテクスチャを全部作り直していたのをやめた
- ツール: 描きかけは ChangeNotifier で、赤い線・ボタン・札の 3 か所だけが描き直す（指が動くたびにページ全体を組み直していた）
- 3D: タイルの貼り付けでビルダーとスタイル表を一片ごとに作らない。被覆・描く順・範囲の走査で一時リストを作らない。
  ラベルの順は並びが変わったときだけ並べ直す
- 背景地図: 初期化を 1 回に（main と地図ページの両方から呼ばれ、そのたびにキャッシュ DB を開き直していた）。
  同じ親タイルの同時取得を 1 本に、存在しない段を取りに行かない、一括ダウンロードの待ち行列が 2 乗だったのを直した
- GeoPackage: PRAGMA table_info と主キー名を控える（列・レイヤの変更と接続の開閉で捨てる）。レイヤの移植を 1 回の読み出しに
- Drive 同期: 判定で集めた一覧を push / pull / マージに渡す（衝突時に Drive を 4 回たどっていたのが 1 回）
- 属性表: 行のチェックで表全体を組み直さない。1 マスごとの await をやめた
- GPS: 長押し測量で点の一覧を毎回複製しない。水準器の 2 秒タイマーをやめ GPS の通知で組み直す
- 位置共有: 他メンバーの位置が同じなら流さない（自分が送るたびに地図ページを組み直していた）

## 2026-10-12 大きさとメモリ（n9/size-mem）

PC だけで測れる分を直した。メモリは端末で測っていない（[[TODO#8. メモリ・大きさ（profile 版と DevTools。n9/size-mem）]]）。

### APK の大きさ

`flutter build apk --release --analyze-size --target-platform android-arm64` で測った（Play は AAB から ABI ごとに配るので、arm64 の分が利用者のダウンロード）。

| 項目 | 前 | 後 |
|---|---|---|
| APK（この測り方。jniLibs の他 ABI の GDAL も入る） | 122,312,648 B | 120,368,746 B（−1.94MB） |
| `flutter_assets`（圧縮後） | 約 7.2MB | 5.3MB |
| 更新履歴の図解 SVG（270 枚・圧縮後） | 3.31MB | 2.75MB |

arm64 の中身（圧縮後）: libgdal 20.1MB・libapp（Dart AOT）19.1MB・libflutter 11.7MB・libbarhopper（QR 読み取り）4.9MB・
libgeodiff 2.8MB・libsqlite3 1.7MB・proj.db 1.9MB（元 10.5MB）・dex 2.3MB。.so は `Stored`（圧縮せず APK に置き、端末で展開しない）。

- **使われないフォント**: trina_grid → shadcn_ui → lucide_icons_flutter が太さ違いの Lucide（`Lucide100`〜`600`、計 2.8MB・圧縮後 1.37MB）を
  宣言している。アプリの Dart コードはこのファミリを引かない（libapp.so にファミリ名が無いのを確かめた）。アイコンの刈り込みは
  使われたファミリだけを見るので、丸ごと入っていた。`android/app/build.gradle.kts` で `copyFlutterAssets*` から外し、
  `FontManifest.json` からも消す。web には効いていない（TODO）
- **図解の SVG の id**: Typst は字形ごとに `g` + 32 桁の 16 進の id を振り、`<use>` で何度も引く。`tool/changelog/build.py` の
  `_short_ids` で短い名前に付け替える（形・座標は変えない。vector_graphics の符号化結果がバイト単位で同じなのを確かめた）。
  既にある SVG は `python tool/changelog/build.py --short-ids` で付け替えた。参照切れはテスト（`changelog_figure_test`）で見る

触らなかったもの:

- ネイティブの .so はどれも strip 済み（`file` で確認）。GDAL の機能を削るのは別の話
- proj.db: 利用者の任意の CRS を読むので削らない
- x86_64: 一部の Chromebook が要る。Play は ABI ごとに配るので arm64 の利用者のダウンロードには乗らない
- Geist（shadcn_ui のフォント、計 340KB）は AOT に名前があり、使われうるので残した
- mlkit の QR モデル（860KB）・barhopper: QR の読み取りに要る

### メモリ

| 直したこと | 見込み |
|---|---|
| 地形タイルが縁を借りた隣を強く持っていた。`trim` で捨てたタイルが隣の参照で数珠つなぎに残り、同じ段でパンし続けるほど標高（約 0.5MB）とメッシュ（1 段 数 MB）が溜まっていた。弱い参照にし、`dispose` でメッシュも手放す | 長いパンで 1 枚 1〜5MB × 捨てた枚数（上限なし → 40 枚＋α） |
| 地図の初期化（await の途中）で画面が閉じると、閉じた後に聞き手・コンパスの購読・GPS の開始・自動同期の起動が付き、画面ごと残っていた。各所で `mounted` を見る | 開きかけで戻るたびに地図の画面 1 つ分（数十〜数百 MB） |
| 自動同期が閉じた地図の画面の呼び戻しを次に開くまで持っていた。画面を閉じたら `AutoSyncService.detach()` | 画面 1 つ分（次に開くまで） |
| OS がメモリ不足を知らせたとき（`didHaveMemoryPressure`）・裏に回ったときに、タイル画像の LRU（最大 64MB）と DEM の LRU を手放す。貼ってあるタイルは残すので絵は変わらない | 最大 約 70MB（裏にいる間に落とされにくく） |
| 情報パネルに薄く敷く写真を原寸でデコードしていた（1200 万画素で約 48MB、閉じた後も imageCache に残る）。パネルの長辺 × 画面密度（上限 2048px）に縮めてデコード | 1 枚 48MB → 数 MB |
| Flutter の imageCache の上限を 100MB → 40MB（`main.dart` の `_imageCacheBytes`）。原寸の写真は閉じたら残さない。表示中の画像は上限に関係ない | 最大 60MB |
| タイルのデコードのコーデック、読み込み中に地図が閉じたオーバーレイ画像を、GC を待たずに手放す | 小 |

## 2026-10-12 置いたままの焼き直し（d2/rebake-loop）

Pixel 9 で地図を開いて置いたまま（GPS 記録中）、20 秒ごとに `Consolidation完了` → `[Features]` → `[3D] bake: 6 枚を世代 N で焼き直す` が続いていた。
10-06 の直し（[[#地物の一覧を保つ]]）で全タイルの焼き直しは止まっていたが、まだ次が残っていた。

- 統合のたびに `updateFeatures()`（全レイヤの地物を集め直し → 全件の組み直し → 1.5 万面の署名を取り直す）を引いていた。
  今は `syncConsolidatedTrack`（`lib/screens/map_page/gps_track_sync.dart`）が今日の 1 本を差し替え、軌跡のレイヤが見えていればその 1 本だけ
  `refreshFeatureRows` → `SceneSink.pushFeatureChanges` → `FeatureGeoJsonCache.rebuildFeatures` で差分で流す（面のリストは同じもののまま）。
  レイヤが見えていなければ地図は触らない。差し替えられない（今日の区間がまだ地図に無い）ときだけレイヤを読み直して全件を組み直す
- 変わった範囲が「今日の軌跡全体」だった（前の形と今の形の範囲を合わせていた）。線の後ろに点を足しただけ（前の座標がそのまま先頭に並ぶ）なら、
  前の最後の点から足した点までの範囲にする（`_changedBox`）
- 寄った段（z14 以上）のテクスチャは面の塗りしか焼かないのに、線の変化でも焼き直していた。`FeatureGeoJsonCache.lastChangeHasFills` を出来事に載せ、
  線・点だけの変化では寄った段を焼き直さない。台帳は `FeatureBakeLedger`（`lib/core/terrain/feature_bake_ledger.dart`）に切り出した
  （タイルの形の作り直し＝シーンは寄った段で線も描くので、こちらは今までどおり範囲で見る）

テスト: `test/gps_track_sync_test.dart`・`test/feature_bake_ledger_test.dart`。

### 1 texel に届かない線の伸びは焼き直さない（d2/bake-subpixel）

上の直しの後も、z7 ほどに引いて置いたままで 20 秒ごとに `Consolidation完了 (4点反映)` → `[3D] bake: 6 枚` →
`bake z7 …: 56 件 45ms`・`bake z8 …: 36ms` が続いた（約 90 ms）。足した 4 点は GPS の揺れ数 m で、z5〜z8 の 1 texel（数百 m）にまったく届かない。

- `FeatureGeoJsonCache.lastChangeExtension`: 変化が全部「線の後ろに点を足しただけ」（面でなく、線の本数も属性も変わらない）なら、その区間の範囲。
  描いた・消した・途中が動いた・属性やスタイルを変えた・新しい本が増えた（短くても丸い点として現れる）は null で、今までどおり必ず焼く
- 台帳（`FeatureBakeLedger.addEvent(..., extension:)`）はその範囲を出来事に載せ、`takeStale` でタイルごとに
  「まだ焼いていない伸び」（`pending`）と合わせた範囲の対角がそのタイルのテクスチャの 1 texel（`texelOf`。地図面では
  `metersPerPixel(z + textureZoomOffsetFor(z))`、z13 以下は 512² なので z7 で約 610 m・z13 で約 9.6 m）に届かなければ焼かずに貯める。
  届いたら焼き、そのタイルのテクスチャを貼れば貯めは消える（描いた世代が貯めた世代以降のとき）。オーバーレイなど別の作り直しで貼っても消える
- 線は丸い端・丸い継ぎ目で描くので、足した区間で塗りが変わるのは前の端点から足した点までの距離の内側だけで、線の太さに依らない。
  なので比べるのは区間の範囲の対角と 1 texel だけ（膨らませた 50 m は掛かるタイルを探すためのもので、比べには使わない）
- 寄れば細かい段のタイルが今の中身で新しく焼かれるので、見ている所で軌跡がずれることはない。粗い段の貯めも歩けば 1 texel ごとに焼かれる
- `[3D] bake: N 枚を世代 G で焼き直した` は貼り終えてから実際に貼った枚数を出す（打ち切り・見送りの枚数は括弧で）

テスト: `test/feature_bake_ledger_test.dart`（見送り・貯めて焼く・必ず焼く変化・段ごとの texel）・`test/gps_track_sync_test.dart`（`lastChangeExtension`）。
端末での確かめは未（引いて置いたままで `[3D] bake` が出ないこと、歩けば粗い段も追いつくこと）。

## 測り方のメモ

- CPU: `adb shell top -b -n 1 -p $(pidof com.k_root.k_maps)` の `%CPU`。読み込み直後は高いので落ち着いてから
- メモリ: `dumpsys meminfo com.k_root.k_maps`。GPU は `GL mtrack`。debug は JIT の分が Private Other に乗る
- profile 版は debug と同じ鍵で署名されるので、アンインストールせずに上書きできる（端末のデータが消えない）
